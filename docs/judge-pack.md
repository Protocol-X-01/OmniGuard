This pack needs no wallet, chain connection, compiler or local build. Install the production Forge app on a Jira site you administer, then open a project with a **Task** issue type. The reviewing user needs permission to browse/create issues, add comments and use a Done transition. Jira administrators install the app; project users act through their own Jira permissions.

The requested permissions are Jira work read/write and Forge storage. Imported bundles contain full selected fixture source, report data, hashes and metadata. Forge retains import times and remediation history. New imports do not store importer account IDs; a project administrator can permanently remove that field from older scans under **Data management**. Distinct source snapshots and remediation history remain stored without automatic expiry or an in-app deletion control for those records. Jira evidence copies follow Jira permissions. Use the supplied isolated fixtures.

1. Open the Jira project and select **OmniGuard** in its Apps/navigation menu.
2. Choose `reports/vulnerable.omniguard.json`, then **Import scan report**. Alternatively use **Paste a report instead → Use pasted report**, then import.
3. Expect one **OG-SOL-002** finding, engine **0.1.4**, **solc 0.8.26** and complete 12-rule coverage. Inspect the helper interaction, later storage write, source excerpts and hashes.
4. Choose **Create Jira remediation**. Open the new Task and inspect its source evidence and analysis baseline. Refresh OmniGuard; the issue should remain linked.
5. Import `reports/fixed-source-only.omniguard.json`. Although it has zero findings, verification must stay disabled because the analysis mode/compiler differs. This is an intentional negative check.
6. Import `reports/fixed.omniguard.json`. Expect zero findings under the matching compiler profile. Choose **Record rescan verification in Jira** and inspect the actual comment and before/after source hashes.
7. Review `sources/vulnerable/EffectVault.sol` and `sources/fixed/EffectVault.sol`. The fix moves the storage reset before the helper call. Choose **Move to Done**, or the available completion transition in your workflow.
8. Reload both app and Jira issue. Confirm the fixed scan, issue, verification and Done status persist.

For unavailable actions, check the project's Task type, required fields, permissions and workflow. Do not weaken the report profile to work around an incomplete scan. A repeated creation request for the same finding should return the existing issue. Verification is rule absence in an imported report, not proof of safety or scanner execution.

The Rust scanner and Forge app are independently buildable. The source release contains three local EVM witnesses, including a 128-run paired fuzz property. Its frozen synthetic review matches 24/26 labels; explicit-super dispatch and one composed-modifier case remain incomplete. The Bitbucket integration is a separate scaffold, not live PR scanning.
